# Portfolio — Trần Đình Võ

Personal portfolio site. Its job is to get the owner interviews for a
**full-stack / backend internship**, so every decision is judged on: does this
make a recruiter or engineer trust him more in the ~60 seconds they will spend here?

The owner is a final-year IT student at UTC2 (HCMC) who builds financial systems.
He is a **Vietnamese speaker** — write explanations to him in Vietnamese, but the
site content itself is English (see Open decisions).

**Next.js 16 is not the version in your training data.** Read
`node_modules/next/dist/docs/` before writing framework code. See `AGENTS.md`
— that block is regenerated by `next dev`, so do not delete it; add project
notes to this file instead.

**Tailwind v4 has no `tailwind.config.js`.** Theme lives in
`src/app/globals.css` under `@theme inline`. Add design tokens there, not in a
config file. Fonts are wired as CSS variables (`--font-geist-sans`,
`--font-geist-mono`) from `next/font/google` in `layout.tsx`.

## Conventions

- **`src/data/` is the single source of truth for content.** Components render
  data, they never hardcode copy. Changing a project description must not
  require touching a component. Import via the barrel: `import { profile, featuredProjects } from "@/data"`.
- Types live in `src/types/index.ts`. Data files are typed against them, so a
  bad edit fails `tsc` instead of rendering wrong.
- Server Components by default. Add `"use client"` only where an interaction
  actually needs it, and push it as far down the tree as possible.
- `cn()` from `@/lib/utils` for conditional class names.

## Content rules — important

The data in `src/data/` is **real**, gathered from the owner's actual repos and
CV. Two hard rules:

1. **Never invent metrics.** No "improved performance by 40%", no fake user
   counts, no made-up client names. If a number would strengthen the site, ask
   him for the real one.
2. **Private projects stay private.** PayHub, FinanceOS, TrendScope, MonkeyMail
   and Pezura are company/internal work with no public repo — they are marked
   `visibility: "private"` and must not link to a repository. Describe the
   engineering, not the client's business data.

## Decisions taken

1. **Visual direction** — blueprint, reusing the GitHub profile language:
   off-white grid paper, monospace labels, corner brackets, blue accent.
2. **Single scrolling page** for the overview — sections `#about` `#skills`
   `#projects` `#awards` `#contact` — plus one case-study route per project at
   `/projects/[slug]`, statically generated. Revised 2026-09-28: the detail
   the projects deserve does not fit on a card.
3. **English only.**

Design tokens live in `src/app/globals.css`. Three blocks write the same token
set: `:root` (light), the `prefers-color-scheme: dark` block, and
`:root[data-theme="dark"]` for the explicit toggle. Components use
`bg-surface` / `text-muted` / `border-line` / `text-accent` and never `dark:`
variants — flipping a token is enough.

Motion is scroll-linked CSS, not JavaScript: `.reveal` uses
`animation-timeline: view()` and the header rule uses `animation-timeline:
scroll()`, both inside `@supports` and `prefers-reduced-motion` guards, so
there is nothing to hydrate and nothing breaks in Safari or Firefox.

Screenshots are the only reliable check. Headless Chrome with a real viewport

`--window-size` screenshots lie, because the hero is sized in `svh`.
